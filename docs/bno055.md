# BNO055 on Orange Pi 5 Plus

The BNO055 is the default 9-axis IMU. Raw and fused ROS topics are enabled by
default for the dashboard.

## Wiring

Power off the Orange Pi before changing connections. These are physical
40-pin header numbers, not GPIO or wiringOP numbers.

| BNO055 breakout | Orange Pi 5 Plus |
| --- | --- |
| `VIN` or `VCC` | Pin 1 - 3.3 V |
| `SDA` | Pin 3 - I2C2_M0 SDA |
| `SCL` | Pin 5 - I2C2_M0 SCL |
| `GND` | Pin 6 - ground |

Use the breakout's power-input pin. Do not connect a pin marked `3Vo`, which is
normally a regulator output, and do not use the Orange Pi's 5 V header pins.
`RST` and `INT` are not required by the current driver.

The pin assignment comes from the official
[Orange Pi 5 Plus documentation](https://www.orangepi.org/orangepiwiki/index.php/Orange_Pi_5_Plus).

## Enable and verify I2C

Enable `i2c2-m0` in `sudo orangepi-config` under **System > Hardware**, save,
and reboot. Then check the bus:

```bash
ls -l /dev/i2c-2
sudo i2cdetect -y 2
```

The project currently expects address `0x29`. The scan should therefore show
`29`; this is an I2C address, not physical pin 29. If it shows `28`, change the
`bno055_node.address` value in an optional `config/ros/boat.local.yaml`.

Stop the ROS IMU node before scanning. An address owned by a kernel driver may
appear as `UU`.

## Run

Launch the default BNO055:

```bash
ros2 launch mtr_boat_core sensors.launch.py
```

Use `imu_driver:=mpu6050` to select the older 6-axis IMU instead.

For a direct bench display without ROS:

```bash
python3 scripts/test_bno055_live.py
```

The node publishes:

| Topic | Meaning |
| --- | --- |
| `/imu/data_raw` | Angular velocity and acceleration including gravity |
| `/imu/mag` | Magnetic field |
| `/imu/temperature` | Sensor temperature |
| `/imu/linear_acceleration` | Device estimate with gravity removed |
| `/imu/gravity` | Device gravity estimate |
| `/diagnostics` | Calibration and system status |
| `/imu/data` | Optional device-fused orientation |

## Orientation safety

The BNO055 quaternion uses Bosch's Android-format convention. The dashboard
shows it for setup and calibration, but the installed roll, pitch, yaw, and
magnetic heading still need a physical check before autonomous navigation
trusts absolute heading. Change `placement` if the displayed axes do not match
the boat.

The `base_link -> imu_link` transform is also off by default. Measure the
installed position and orientation before setting `publish_imu_tf:=true`.

Calibration values range from `0` to `3`. Do not use absolute heading for
navigation until all four values report `3` and the result has been checked
against a known direction.

## Automatic recovery

The ROS node automatically closes and reinitializes the BNO055 after five
consecutive read failures. Reinitialization resets the sensor and restores its
configured placement, SI units, and NDOF fusion mode. If the sensor is still
unavailable, retries back off from one second to a maximum of 30 seconds.

Recovery state and counts are published in the `BNO055 IMU` entry on
`/diagnostics`. Recovery makes a brief I2C or power interruption survivable,
but repeated recoveries still indicate wiring, power, or signal-integrity
trouble that should be fixed before operating on the water.
